# Internationalisation

Coup Online is written in English and translated into Hindi (`hi`), Brazilian
Portuguese (`pt-BR`), Spanish (`es`), Arabic (`ar`, right to left), Simplified
Chinese (`zh-Hans`) and Vietnamese (`vi`). This document is the contract for
everyone who adds a string, converts a component or translates.

The machinery is in-house, about 600 lines with no runtime dependency:

| Where | What |
|---|---|
| `src/shared/i18n/locales.ts` | The language registry (`LOCALES`): native name, direction, Intl tag, status |
| `src/shared/i18n/messageFormat.ts` | ICU MessageFormat subset: interpolation, plurals, select, rich-text tags, numbers, lists |
| `src/shared/i18n/matchLocale.ts` | Locale resolution and `navigator.languages` matching |
| `src/shared/i18n/bootScript.ts` | The pre-paint script: sets `<html lang dir>` and hides the page while a catalog loads |
| `src/shared/i18n/logMessages.ts` | Structured action-log lines: every key and its typed params |
| `src/shared/i18n/serverErrors.ts` | Stable codes for every error or notice text the server sends |
| `src/shared/i18n/pseudo.ts`, `completeness.ts` | Pseudo-locales; catalog checks |
| `src/app/i18n/messages/<locale>/<namespace>.ts` | The catalogs. English is the source of truth |
| `src/app/i18n/registry.ts` | One on-demand loader per translated locale |
| `src/app/i18n/runtime.ts`, `react.tsx`, `index.ts` | `useT()`, `getT()`, switching, fallback |
| `src/app/i18n/glossary.ts` | `characterName`, `actionName`, `factionName`, `phaseName`, `gameModeName` |
| `src/app/i18n/serverErrors.ts` | `describeServerError`, `describeAckError` |
| `src/app/i18n/I18nBootstrap.tsx` | Resolves and applies the locale after hydration, follows Settings |
| `scripts/i18n-report.ts` | `npx tsx scripts/i18n-report.ts [locale]`: translation status per locale |

Why not a library: the app is client-rendered behind a custom Express server,
so the server-component features of next-intl buy nothing, and every client
library adds 10-40KB for a format we use a small part of. The subset here is
standard ICU, so Crowdin, Lokalise or Weblate can read the catalogs if we
ever use one.

## Adding a string

1. Put it in the English catalog for its area, `src/app/i18n/messages/en/<namespace>.ts`.
2. Use it: `const t = useT(); t('lobby.startGame')`. A misspelt key is a
   compile error.
3. Nothing else. Other locales fall back to English until translated, and
   `scripts/i18n-report.ts` lists the new key as missing for each of them.

```tsx
import { useT } from '@/app/i18n';

const t = useT();
t('settings.music');                                  // "Music"
t('glossary.term.coin', { count: 3 });                // "3 coins"
t.rich('prompts.blockOffer', { name: <b>{n}</b> });   // React nodes, one sentence
t.number(1234);                                       // "1,234" in en, "1.234" in pt-BR
t.list([a, b, c]);                                    // "A, B, and C" / "A, B e C"
```

Outside render (socket handlers, callbacks) use `getT()`; it does not re-render.
Inside render always use `useT()`, so a language switch re-renders the component.

### Key naming

- `namespace.key`. Keys are camelCase and say what the string is, not where it
  sits: `log.tabChat`, `settings.languageAuto`, `errors.room_full` (error keys
  are the server's codes, which are snake_case).
- A dotted key inside a namespace groups variants: `glossary.character.Duke`,
  `log.explain.block`.
- One key per sentence. Never build a sentence from fragments.
- Namespaces, one file per locale each, so agents working on different areas
  never touch the same file:

| Namespace | Area |
|---|---|
| `common` | Words that mean the same everywhere (Done, Close, Cancel, Back) |
| `glossary` | The game's nouns: characters, actions, factions, modes, phases, terms |
| `home` | `src/app/page.tsx`, `components/home/` |
| `lobby` | `src/app/lobby/`, `components/lobby/`, `AddBotModal` |
| `game` | The table: seats, dock, header, centre stage, `PhaseStatus`, `ClaimPlaque`, `ActionBar` and its refusals, the drawer chrome |
| `prompts` | Challenge, block, influence loss, exchange and examine prompts, `ChallengeRevealOverlay` |
| `log` | The action log (lines, chrome, practice explanations) |
| `gameover` | `GameOverOverlay` and `components/game/gameover/`: result, final hands, recap, awards, rematch |
| `stats` | The stats modal (`components/stats/`) |
| `feedback` | Toasts, reactions, chat chrome, `TableTalk`, `SeatSpeech` |
| `tutorial` | The new player tutorial and practice coach |
| `rules` | How to Play and the rules reference |
| `errors` | Server error codes (one key per code) and client-side failures |
| `settings` | The Settings modal |
| `seo` | Titles, descriptions, Open Graph text for translated landing pages |

To add a namespace: a file in every locale folder and a line in each folder's
`index.ts`.

## Message syntax

Standard ICU MessageFormat, the subset in `messageFormat.ts`:

| Need | Write |
|---|---|
| A value | `{name}` |
| A number in the reader's format | `{count, number}` (numeric params are formatted anyway) |
| A plural | `{count, plural, one {# coin} other {# coins}}` |
| An exact count | `{count, plural, =0 {no coins} one {# coin} other {# coins}}` |
| A choice | `{actor, select, you {You take} other {{actor} takes}}` |
| Rich text | `Pay <b>{cost, plural, one {# coin} other {# coins}}</b>`, rendered by a `b` function passed to `t.rich` |
| An apostrophe | Type it: `{actor}'s turn`, `can't`. Only `'{`, `'}`, `'<`, `'#` start quoting, and `''` is one apostrophe |

Plurals use `Intl.PluralRules`, so each language writes the categories it has:

| Language | Categories | Example |
|---|---|---|
| English, Spanish | one, other | 1 coin, 2 coins |
| Portuguese (BR) | one (0 and 1), other | 0 moeda, 2 moedas |
| Hindi | one (0 and 1), other | 1 सिक्का, 2 सिक्के |
| Arabic | zero, one, two, few (3-10), many (11-99), other | write all six |
| Chinese, Vietnamese | other | `{count, plural, other {# 枚金币}}` |

Rich text: keep the whole sentence in one message and mark the parts with
tags, never split it. Word order differs by language; a tag can move with
its words.

```tsx
// en: '<b>{actor}</b> is stealing from you. Block with {character}.'
t.rich('prompts.stealBlock', {
  actor: actorName,
  character: <CharacterChip c={Character.Captain} />,   // a React node as a value
  b: (chunks) => <strong>{chunks}</strong>,               // a tag renderer
});
```

## What is never translated

- Anything a player typed: names, chat messages, room codes.
- Wire identifiers: `Character`, `ActionType`, `Faction`, `TurnPhase` enum
  values, event names, error codes, log keys. Show them through the glossary
  helpers (`characterName(t, c)`), never by printing the enum.
- The server's English `message` on log entries and errors. It stays for
  server logs, metrics, bots and older clients; clients render `msg` / `code`.
- Card art. The printed `CAPTAIN` / `STEAL` plates on the raster cards are
  English in the image; the HTML labels over them translate.

## Server text

The server has no per-player locale and needs none: everything it says has a
stable key.

**Log lines.** Every `log` side effect in `ActionResolver` (and the four in
`Game.ts`, one in `GameEngine.ts`, one in `RoomManager.ts`) carries both the
English `message` and `msg: { key, params }`. The `LogMessageParams`
interface in `src/shared/i18n/logMessages.ts` lists every key with its exact
params, `logMsg()` checks them, and a log effect without `msg` does not
compile. Params are typed by name: `actor`, `target`, `challenger`,
`challenged`, `blocker` are player ids; `character`, `action`, `faction` are
enum values; `amount` is a number. Clients name players from
`gameState.players` (stored logs map ids to seats in `anonymizeGameLog`).
`tests/app/i18n/logMessages.test.tsx` plays bot games in every mode and
checks that the English catalog reproduces every server `message` exactly.

To add a log line: add the key and params to `LogMessageParams`, emit it with
`msg: logMsg('key', {...})` beside the English `message`, add the English line
to `messages/en/log.ts` (compile error until you do), and a sample to the
test's `SAMPLES` (also a compile error).

**Errors and notices.** `serverErrors.ts` maps every error text the server
sends (`game:error`, `room:error`, `room:removed`, failed acknowledgements)
to a code and params. `SocketHandler` sends `serverErrorPayload(message)` and
`failedAck(error)`, which add `code`/`params` (`errorCode`/`errorParams` on
acks) beside the English. The client renders with `describeServerError` /
`describeAckError`; an unknown code shows the English. A test scans the
engine and server for error literals and fails on any without a code.

**Feedback.** `feedback:send` already answers with a stable
`FeedbackErrorCode` (`src/shared/feedbackTypes.ts`), never English, so it
needs no entry in `serverErrors.ts`; `FeedbackForm` renders each code as
`feedback.error.<code>`.

**Reactions in chat.** Reaction lines carry `reactionId` on the `ChatMessage`;
the `message` is the English `<emoji> <label>`. Render `reactionId` through
the catalog.

**Quick phrases.** The chat composer's one-tap lines (`QUICK_PHRASES` in
`src/shared/constants.ts`) are sent as `chat:send` with a `phraseId`. The
server stores the phrase's English as `message` and passes `phraseId` on, so
each reader sees the phrase in their own language (`game.phrase.<id>`); an
older client still shows the English. `chatText()` in
`components/game/tableText.tsx` renders any chat line for the reader: typed
text as typed, reactions and phrases from the catalog.

**Refusals.** The ActionBar's reasons for refusing a button or a seat travel
as `{ key, params }` (`Refusal` in `src/shared/types.ts`, keys under
`game.refusal.`), so the seats and the dock word them for the reader.

## Choosing the language

1. A landing page's locale as the first URL path segment (`/pt-br`); no app
   route starts with one.
2. The landing page this browser tab came in through (sessionStorage
   `coup_landing_locale`), on app routes only: a player who opened `/hi`
   and started a game keeps Hindi after a reload mid-game. `/` and any
   choice in Settings clear it.
3. The saved choice, Settings > Language (`settingsStore.locale`, stored as
   `coup_locale`; "Match my device" stores `auto`).
4. The best match in `navigator.languages`: `pt-*` → `pt-BR`, `es-*` → `es`,
   `ar-*` → `ar`, `hi-*` → `hi`, `vi-*` → `vi`, `zh`, `zh-CN`, `zh-SG`,
   `zh-Hans-*` → `zh-Hans`. `en-IN` stays English: Indian players who want
   Hindi choose it. Traditional Chinese (`zh-TW`, `zh-HK`, `zh-MO`,
   `zh-Hant`) is a weak match for `zh-Hans`: used only when no other listed
   language matches, because those readers can read Simplified but many
   would rather read a language they listed, and some find Simplified
   unwelcome. A `zh-Hant` catalog would match them exactly with no code change.
5. English.

Languages with `status: 'in-progress'` are never chosen automatically and
appear in the picker only in development, or in production after
`localStorage.setItem('coup_i18n_preview', '1')` (for reviewers).

No flash of the wrong language: the server renders English (a landing page
in its own language, below), and React hydrates the same language, so there
is no mismatch. Before first paint the inline script resolves the locale
with the same function the app uses, sets `<html lang dir>`, and if the
language differs from the one the server rendered (`data-ssr-locale` on
`<html>`) hides the page (`html.i18n-pending`) until the catalog has
rendered (1.5s backstop). English readers pay nothing; other catalogs are
separate chunks.

## Landing pages and search

Every language whose `status` is `'ready'` has a landing page: `/pt-br`,
`/es`, `/ar`, `/zh-hans`, `/vi`, `/hi` (the registry code in lower case;
English is `/`). Flipping `status` is the whole change: the route
(`src/app/[locale]/`), its sitemap entry, its place in every page's hreflang
set, the footer language switcher and the "read in your language"
suggestion all follow from the registry. In development the pseudo-locales
have pages too (`/en-xa`, `/ar-xb`); unfinished languages never do.

- **Server-rendered in the language.** `[locale]/layout.tsx` loads the
  catalog and hands it to `LandingLocaleProvider`; `useT()` prefers that
  language, so the HTML a crawler receives (and the first client render)
  is translated. `<html lang dir>` comes from the URL (`LocaleHtml`).
- **Metadata** (`src/app/i18n/landing.ts`, from the `seo` namespace):
  title, description, self canonical, hreflang for every landing page plus
  `x-default` (= `/`), Open Graph (`og:locale` from the registry's `og`)
  and Twitter, a manifest per language (`/pt-br/manifest.webmanifest`,
  same app id). Every absolute URL comes from `siteUrl()`
  (`NEXT_PUBLIC_BASE_URL`, read at build time).
- **Content.** `components/home/SeoContent.tsx` renders the About section,
  FAQ, credit, language switcher and JSON-LD (`WebSite`, `VideoGame`,
  `FAQPage`, each with `inLanguage`) under the menu on every landing page.
- **One URL per page.** `/PT-BR` and `/en` redirect (308) in `server.ts`;
  an unknown locale is a 404; `/pt-br/` loses its slash.
- **People.** Landing pages never redirect by language. On `/`, a reader
  seeing English whose browser also lists a ready language gets a
  dismissible suggestion. The switcher and Settings > Language save the
  choice and move to that language's page; invite links (`/lobby/CODE`,
  `/game/CODE`) stay unprefixed.
- **Checks.** `npx tsx scripts/check-seo.ts <origin>` reads a running
  server's sitemap and pages as a crawler would; `tests/app/i18n/landing*.ts`
  cover routes, metadata, hreflang reciprocity, robots and rendering.

## Adding a language

1. A line in `LOCALES` (`src/shared/i18n/locales.ts`): native name, direction,
   Intl tag, `status: 'in-progress'`.
2. A folder `src/app/i18n/messages/<code>/` with one file per namespace and an
   `index.ts` (copy any other locale's folder; every file starts as `{}`).
3. A loader line in `src/app/i18n/registry.ts`.
4. Fonts and `:lang()` rules in `globals.css` if the script needs them (below).
5. Its glossary below, then translate, then flip `status` to `'ready'`.

## Pseudo-locales (development only)

Settings > Language in a dev build lists two extra entries:

- **Ƥšéúðö (accented)**, `en-XA`: every catalog string accented, vowels doubled
  (about 35% longer) and wrapped in `⟦ ⟧`. Text on screen without brackets is
  still hard-coded. Layouts that only fit English show it.
- **Pseudo RTL**, `ar-XB`: English under `dir="rtl"`, each catalog string in a
  right-to-left override, wrapped in `⟦ ⟧`, and the Arabic type rules on.
  Mirroring bugs show without reading Arabic.

Names, numbers and other params are never transformed. Neither locale exists
in a production build.

## Type

| Script | Display | Body |
|---|---|---|
| Latin, Vietnamese | Oswald, vendored per subset (latin 28KB preloaded; latin-ext 24KB and vietnamese 8KB fetched only when a glyph needs them, by `unicode-range`) | system |
| Arabic | Noto Kufi Arabic, vendored (124KB, Arabic range only, fetched only by Arabic readers) | system (SF Arabic / Geeza Pro, Segoe UI, Noto) |
| Devanagari | system (Kohinoor Devanagari, Nirmala UI, Noto Sans Devanagari) | system |
| Chinese | system (PingFang SC, Microsoft YaHei, Noto Sans CJK SC) | system |

Latin inside any of them (player names) stays Oswald. Why: a geometric Kufi
is the Arabic counterpart of a condensed civic grotesque and Android's system
Arabic is a book face, so Arabic earns a vendored font. A Chinese face is
4-8MB even sliced. For Hindi the candidates were Teko (condensed, 64KB) and
Noto Sans Devanagari (207KB); condensed Devanagari crowds its matras and every
platform ships a good Devanagari sans, so it is not worth the bytes on Indian
mobile data. The CSP is `font-src 'self'`: fonts are always self-hosted.

Under `:lang(ar)`, `:lang(zh)` and `:lang(hi)`: no letter-spacing (it breaks
Arabic joins and Devanagari conjuncts), no `uppercase`, no faux italics, and
display type in a normal-width face. Under `:lang(hi)` every line box is 1.5
so vowel marks above the headline and below the baseline are not clipped in
buttons, seats and the log.

## Right to left

Set by `<html dir>` from the registry. The rule:

- **Mirrors:** text blocks, prompts, the log, chat, forms, the dock, modals,
  the header. They must use logical properties: `ms-/me-/ps-/pe-`,
  `start-/end-`, `text-start`, `border-inline-start`, `margin-inline-end`.
  A physical `left`/`right`/`ml-`/`pl-`/`text-left` on text is a bug.
- **Does not mirror:** the court table (`.court-table`): the oval, seat
  positions, deck, treasury, discard, coin and card flights. It is a physical
  object and every reader at the table must see the same seat in the same
  place. `globals.css` pins it to `direction: ltr` and isolates text inside
  seats so names read in their own direction.
- **Figures** (`.figure`: coins, timers, room codes) always read left to right.
- Player names inside sentences go in `<bdi>` (the log does this).
- Icons that point (arrows, chevrons, "next") flip; icons that depict
  (emblems, coins, the crown) do not.

## Voice

Translations follow `docs/VOICE.md` in their own language: plain sentences,
the game's own nouns from the glossary below every time, real numbers, verb
buttons, no slogans, rhetorical questions, exclamation marks or capitals for
emphasis.

## Hand-off for phase 2 (string extraction)

The worked example is the action log: `ActionLog.tsx`, `table/LogTicker.tsx`,
`GameCenterTabs.tsx` and the shared renderer `components/game/LogLine.tsx`.
`SettingsModal.tsx` and the in-game feedback form (`components/feedback/FeedbackForm.tsx`) are fully converted too.

### Converting a component

Before:

```tsx
<span className="text-sm">{player.name} must lose a card</span>
<button onClick={onBlock}>Block with {character}</button>
<p>You have {coins} coin{coins === 1 ? '' : 's'}.</p>
```

After (`messages/en/prompts.ts` gets three keys):

```ts
mustLose: '<b>{player}</b> must lose a card.',
blockWith: 'Block with {character}',
youHaveCoins: 'You have {count, plural, one {# coin} other {# coins}}.',
```

```tsx
import { useT, characterName } from '@/app/i18n';

const t = useT();
<span className="text-sm">{t.rich('prompts.mustLose', { player: <bdi>{player.name}</bdi>, b: (c) => <strong>{c}</strong> })}</span>
<button onClick={onBlock}>{t('prompts.blockWith', { character: characterName(t, character) })}</button>
<p>{t('prompts.youHaveCoins', { count: coins })}</p>
```

Rules of thumb: whole sentences per key; plurals in the message, never in
code; names through `<bdi>`; game nouns through the glossary helpers; no
`toUpperCase()` on translated text (use CSS, which `:lang()` neutralises);
logical CSS properties; aria-labels and `title`s are strings too.

### Things noticed in files this phase did not own

- `utils/gameStats.ts` reads amounts out of `entry.message` with English
  regexes (`/steals (\d+) coin/`, `Treasury Reserve \((\d+) coins?\)`). Read
  `entry.msg.params.amount` instead; the regexes keep working only because
  the server English is unchanged.
- `GameOverOverlay.tsx` copies the log as `entry.message` (English) and its
  award details pass `entry.message` through `formatLogMessage`. Use
  `logLinePlain(entry, t, names, myId)` from `src/app/i18n/logText.ts` for the
  copy, and render award details with `renderLogText` from `LogLine.tsx`.
  `ActionLog`'s `myName` prop is now unused and optional.
- `TargetingPublication.reasons` (`src/shared/types.ts`) carries refusal
  sentences as English strings from `ActionBar`; carry a key and params.
- `REACTIONS` labels, `BOT_PERSONALITIES` names and `ACTION_DEFINITIONS`
  descriptions in `src/shared/constants.ts` are English display text in a
  shared constant; keep the ids, move the text to `feedback` / `lobby` /
  `game`. `ChatPanel`, `TableTalk` and `SeatSpeech` should render
  `ChatMessage.reactionId` through the catalog instead of `message`.
- `useSocket.ts` now renders server errors by code, but its own fallbacks
  ("Failed to create room", "Request timed out") and `page.tsx`'s
  ("An error occurred") are English; move them to `errors`.
- The log drawer (`.court-drawer`) slides in from the physical right; under
  `dir="rtl"` it should come from the left (`inset-inline-end`).
- `GameTable.tsx` header and drawer title ("Turn 8", "Log & chat") and every
  `aria-label` there are hard-coded; the pseudo-locale shows them without
  brackets.
- Card label plates (`CardArtwork`, `.card-character-label`) are sized for
  English names at 6-10px; Hindi and Arabic names are longer and taller.
- `layout.tsx` metadata is English; the SEO agent should build per-locale
  metadata from the `seo` namespace for the `/<locale>/` landing pages.
